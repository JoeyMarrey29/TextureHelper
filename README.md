# PERPHEADS Texture Helper

Windows desktop prototype for finding PERPHEADS models, inspecting their textures and UVs, and preparing first-person custom skins. The app runs locally in a Tauri/WebView2 window; no hosting is needed.

**[Download the latest Windows release](https://github.com/JoeyMarrey29/TextureHelper/releases/latest)** · **[Quick usage guide](HELP.md)** · **[Report a bug](https://github.com/JoeyMarrey29/TextureHelper/issues)**

Unofficial, open-source software under [GPL-3.0](LICENSE). PERPHEADS and Garry's Mod game assets are not included or relicensed; users supply their installed content. Three.js retains its [MIT license](ui/vendor/THREE-LICENSE.txt).

## Run

Use the Setup executable from GitHub Releases for automatic updates. The button immediately beside the logo checks stable releases on startup, displays the release log, and asks before downloading/installing. Drafts must save successfully before the app closes for installation. Update packages are verified with an embedded public signing key. Manual Setup downloads and SHA256 checksums are also provided, following the public demo player's release distribution pattern. Portable development builds are not the supported automatic-update install channel.

Double-click the prebuilt `src-tauri/target/release/texture-helper.exe`. It runs locally and requires the Microsoft Edge WebView2 Runtime, which is included on most current Windows systems.

Pass `--minimized` to start without focusing the window, for example while gaming.

To run from source, install the Rust MSVC toolchain and run:

```powershell
cd src-tauri
cargo run
```

### Publishing a release

Update both versions in `src-tauri/Cargo.toml` and `src-tauri/tauri.conf.json`, add `releases/<version>.md`, run the tests, then commit and push `main`. Install the release CLI with `cargo install tauri-cli --locked`. Run `.\tools\release.ps1 -Publish` to build a signed Windows Setup, publish versioned GitHub assets, checksums, release notes and `latest.json`.

The private updater signing key must stay outside Git and must be backed up securely. The script accepts `TAURI_SIGNING_PRIVATE_KEY` and `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`, or uses a private local key under `%LOCALAPPDATA%\TextureHelperRelease`. Losing the key prevents existing installations from trusting future updates. Never commit it. Signed updater payloads are separate from Windows Authenticode signing; current builds may trigger SmartScreen warnings.

Choose your `GarrysMod/garrysmod` folder. The app indexes GMA archives in `addons` and `steamapps/workshop/content/4000`, loose content files, and Garry's Mod/Source VPKs for material fallback. You can also choose a folder of extracted content for inspection. Use **Refresh models** to save the current draft and rescan that folder for new or changed content without choosing it again.

## Workflow

Share complete skins from **Custom skins > Export skin** as self-contained `.phskin` packages. **Import skin** beside the library heading creates a new local copy without installing or replacing existing drafts. Editable drafts retain their textures, materials, alpha choices and loadout; uninstalled backups and installed-only skins retain their VMT/VTF files. See [sharing instructions and limits](HELP.md#share-complete-skins).

**Skin Workshop (development):** browse community skins inside the main app and download them as editable local drafts, never automatic installations. **Back to editor** returns to your work. Publishing an editable draft captures a preview and requires Steam sign-in in your default browser plus explicit public-sharing consent. Submissions queue for automated validation before appearing publicly; use **Refresh** to check their status. See [service setup and security boundaries](workshop/README.md).

**Pending submissions** shows your queued and unsuccessful uploads. You can cancel your own pending uploads and remove failed or cancelled entries; moderators can manage everyone's. Removal cleans up files but retains the server audit record and quota accounting. The moderator-only **Bans** tab provides a searchable, paginated ban table with reasons, profile links and Unban buttons. Cards show uploaders' cached Steam names and profile pictures, and the account header shows your Steam name and avatar. Names are for display only: permissions always use verified SteamIDs. Bans restrict Workshop access, not the offline editor. Steam sign-in opens a localhost handoff page in your browser; return to the app after it confirms the handoff.

Failed uploads show the recorded failure reason. Older failures may have no recorded detail. Workshop confirmations use in-app dialogs rather than browser-origin popups.

Use **Cancel** beside **Publish skin** to discard the staged publishing form without deleting the saved local skin. The trusted Workshop model catalogue includes editor-compatible melee weapons such as the katana, not only guns with attachment mappings.

Sign in with Steam before choosing **Publish to workshop** on a saved skin. Signed-out publishing opens the Workshop sign-in screen without opening the publishing form or preparing a preview; choose Publish again after signing in.

Workshop uploads allow **40 attempts per account per UTC day**, with **4,000 attempts per day across everyone** and no lifetime cap. Failed or removed uploads count for that day; limits reset at midnight UTC. Free infrastructure limits may make the service unavailable before these application limits are reached.

Custom skin draft cards show lazy-loaded previews with saved texture edits and attachment choices. Click a card (or focus it and press Enter) to open the draft. Publish, Export skin, Install/Uninstall and Delete skin are in the draft inspector; backups and installed-only skins retain their library actions.

Autosaves refresh draft status without rescanning installed skins or the texture library, and selection/name-only saves retain cached draft thumbnails. Full library discovery still runs on refresh and window focus. Mesh UV coordinate text is generated only while its details panel is open.
The 3D preview redraws on interaction and when original or edited textures finish loading, without continuously rendering while idle.

Deleting the open draft waits for pending saves and blocks new autosaves until deletion completes, then returns the editor to the component overview with no saved-draft association. You can switch models without trying to save the deleted draft.

To edit an older installed skin, choose your Garry's Mod folder and **Refresh models**, then use **Open as editable draft** on its installed-only card in **Custom skins**. Confirm a matching model before creating the local copy. Only that model's installed materials are imported; old folders do not record weapon attachment selections. Repeating an unchanged import reopens the existing matching draft. Missing files, unmatched materials or non-standard texture mappings are reported rather than guessed; Export skin remains available for backups. No installed files are changed during import.

Fresh models/drafts use original content textures, not overrides from `addons/skins`. Original indexed first-person materials take precedence over loose addon overrides. Saved drafts still apply their own edits explicitly; refresh models after updating to rebuild the original-content index.

### Texture variants

The **Textures** library tab keeps reusable VMT + VTF pairs separately from whole-skin drafts. Workshop downloads and **Import skin** (`.phskin`) automatically add their composed texture pairs to the library, deduplicating existing pairs and retaining custom library names. This does not install anything into Garry's Mod. PNG, DDS, VTF, clipboard and installed-skin editing imports update only the draft; they do not automatically add library entries. Image imports generate a VTF with mipmaps when installed. To import a custom material too, select its VMT and the VTF named by its `$basetexture` together. The pair is associated with the selected original material/texture paths, not guessed from its filename.

Uploads and clipboard images can use a different resolution from the original: for example, 1024 x 1024 can replace 512 x 512, and 2048 x 1024 can replace 1024 x 512. Model UVs address positions across the texture, not fixed pixels ([Garry's Mod UV documentation](https://wiki.facepunch.com/gmod/Structures/MeshVertex)). The app requires the original aspect ratio, power-of-two width and height, and at most 4096 pixels per side. These are compatibility/resource guardrails, not a requirement to match the original size. Unsupported sizes or aspect ratios offer **Resize and import** to the original dimensions, warning that this may distort the image or reduce detail. Cancel leaves the texture unchanged; supported same-ratio images import unchanged without a prompt. Higher resolutions use more memory and do not add detail to a low-resolution source.

Use **Save current variant** to name and keep the selected texture, or **Export draft textures to library** in the saved-draft actions to copy the draft's composed output textures. Component UV regions are combined into the same atlas used for installation, including components restored to their original image; individual component source atlases are not exported by this action. Conflicting component edits block export. Identical pairs are deduplicated; saving one with a new name updates its library label. Unchanged original pairs are omitted from the library when original content is available: use **Original / default** instead. Reusing an existing variant in another draft does not create another library copy.

Click a Textures card to view its image and VMT script. Library cards and the VMT/VTF viewer display opaque RGB, ignoring alpha masks for visibility without changing the saved alpha. Different variants sharing a name receive distinct Alpha mask / Opaque labels (and numbers where needed). The **Skin variant** selector below Selected texture offers only variants with the same original VMT/VTF paths, the same aspect ratio and supported power-of-two dimensions, regardless of original resolution. Switching a suppressor variant preserves unrelated body/stock edits; materials sharing one VTF still change together. **Original / default** restores that texture's original image and material in the draft. Choosing a variant never installs it automatically.

Use **Rename** on a Textures card to change its library label. This keeps the same variant identity, pixels, VMT/VTF paths, draft contents and installed files. Refreshing existing sources will not replace your chosen name.

With no texture selected, the right panel shows **Shared textures** first (when multiple mounted components use an atlas), followed by **Components**. Shared cards identify their component owners; clicking one opens the shared editor and highlights those owners. Component cards show in-game part names and matching saved variants. Each component diagram colours only that component's affected geometry; grey geometry is context. Click a component card or double-click geometry to edit that component in the right panel. Changing a card's variant dropdown applies to that component without opening its editor. When a texture is selected, the highlighted-part preview appears directly under the panel heading; shared-texture selection highlights all of its component owners. Component imports and variants affect only that component in the 3D preview, even if other parts share its VMT/VTF. **Original / default** restores only that component's image. VMT shader settings remain shared and are not taken from component variants.

Single-click geometry to edit its shared atlas; double-click geometry or choose a component card to edit only that component. The variant section contains only **Skin variant** and **Save current variant**; selection details appear in the highlighted preview above and texture tools below. Component mode shows only that component's UV overlay, controlled by **Show mesh UV triangles**; per-component overlay checkboxes appear only in shared mode when multiple mounted components have geometry using that texture. **All components** / click empty 3D space returns to the overview. Importing in shared mode intentionally replaces the whole atlas and clears its component-specific overrides.

Shared cards show the applied saved variant name, original/default, current draft texture, or combined component textures. Reopening a draft matches component pixels against saved library pairs so its component selectors recover saved variant names; component matching ignores variant shader differences because component edits retain the shared VMT shader.

Drafts retain individual component source images across saves and reopening, without installing anything. Identical component PNG data is stored once per draft, while each component keeps its own assignment; shared UV owners still produce one flattened output VTF per original VTF path. Installation, PNG/DDS texture export, `.phskin` export and Workshop publishing automatically combine component UV regions into one atlas, preserving RGBA (including hidden colour under transparent pixels). Mixed-resolution atlases use the largest source resolution (including the shared base), scaling smaller sources with nearest-neighbour sampling to preserve hidden RGB and alpha. UV overlays and pixel coordinates use the selected image's actual resolution. Exported/published skins contain the flattened atlas for compatibility; the local editable draft keeps its separate choices. Conflicting overlapping RGBA pixels block output with an explicit error, while still allowing the unfinished draft to save. Identical overlaps are safe. Composition supports up to 32 sources per atlas, textures up to 4096 x 4096, and a 64-million-pixel working limit across sources and across output pixels times layer count; excessive UV tiling is rejected. Two-texel padding outside occupied regions reduces filtering seams but cannot guarantee isolation at every mip level.

Variants persist locally across restarts. Existing drafts and archived material/texture pairs are not scanned automatically; export them explicitly from a draft when you want library copies. New Workshop downloads and `.phskin` imports add library copies at import time. Existing library entries are kept until you delete them. Skins installed in the selected GMod folder are discovered when the library refreshes, including after **Refresh models**. Identical pairs are shown once. Discovery never creates a whole-skin draft or changes installed files. Installed pairs use original indexed material mappings when available; without them the pair remains viewable under its actual texture path rather than guessing an association.

Deleting a Textures entry removes only the reusable pair, not copies already in drafts or installed game files. Unchanged source pairs stay deleted on subsequent refreshes; a changed source can add a new variant. Saving supports explicit `$basetexture` VMTs and single-frame 2D textures with power-of-two dimensions up to 4096 x 4096. Missing, invalid or unsupported source pairs are listed in the Textures tab's warning details without preventing other textures or drafts from loading. Textures without complete material/texture mappings remain previewable in drafts but cannot be saved as pairs.

1. The library opens on **Compatible** models: finished `c_` weapons, attachment models, and magazines with a referenced weapon VMT and VTF under `models/weapons/v_models` or `models/jarheads/weapons`. Reticles are excluded because PERPHEADS skips them when loading custom skins. Crafting components are excluded. Switch to **All models** to inspect the rest. Filter either view by Weapons, Sight, Stock, Muzzle, Magazine, Underbarrel, Laser, Rails / Mounts, or Iron sights, or search its paths. Attachment categories use the Lua-defined slot rather than treating every weapon-folder model as a weapon. Each tile shows a rendered thumbnail, and the detail view shows its exact source file or GMA path.
2. Hold right click and drag the 3D view to rotate freely, Shift+right-drag to roll, and scroll to zoom. Left-click a mesh to open its texture, VMT and UVs in the right-hand editor and highlight all mounted parts sharing that VTF. Left-drag does not rotate or select; clicking empty space clears highlights and returns to the component overview. The editor shows only the active texture rather than a long material list. Use Reset, Front, Side, or Top for quick views. Each PERPHEADS gun shows its **Attachment slots**: Sight, Stock, Muzzle (suppressors, compensators, and flash hiders), Underbarrel (flashlights), Laser, Magazine, and other slots the gun supports. Each slot lists every compatible item, with its item ID, and you choose what is fitted. The assembly follows the game's `GetAttachmentList` rules: rails or mounts that a part requires (for example `Rifle rail 1` under an AK101 sight, or `Scope rail 2` for the Schmidt & Bender scope) and the gun's default parts (such as the AK101 magazine or M4A1 flip sights) are added automatically and shown as read-only rows. Every part is bonemerged onto the gun bone that shares its root bone name, as the game does with `EF_BONEMERGE`.
   Choose **No part** in the Magazine slot to hide even an automatically added magazine; choose **Default** to restore it. This preview-only override does not change the game's attachment rules.
   Gun meshes and mounting bones use the first idle-animation frame, so animation-positioned parts such as the G36 magazine seat correctly. Flip-up iron sights use their Lua-selected sequence: raised without an optic, folded with an optic.
   The material inspector also shows the GMA, VPK, or loose file that supplied each VMT and VTF.
   Base-texture lookup normalizes Source slashes, optional `materials/` prefixes and explicit `.vtf`/mistaken `.vmt` suffixes. Quoted texture paths containing spaces are preserved, including Jarheads sight mounts.
   Materials sharing the same VTF appear as one texture entry, listing every part that uses it. Each part/material has a separately colored UV overlay with its own visibility checkbox; the UV coordinate list and exported overlay follow those choices. Importing a texture updates all mounted materials sharing that VTF while preserving their individual VMT settings.
   Click the active texture summary to highlight its matching meshes in their UV overlay colors, or use a UV layer's **Highlight** button to identify just that part in the same color. Clicking empty space clears highlights; right-dragging retains them. This temporary overlay never changes textures, UVs, exports, or saved drafts.
   UVs outside 0–1 repeat onto the texture image, and the coordinate list shows their wrapped pixel positions. The preview and thumbnails follow VMT alpha test, translucency, additive blending, and `UnlitGeneric` settings, so sight reticles do not show opaque black backgrounds. Imported texture previews retain these material settings.
3. The texture panel and material swatches show RGB by default: Source often uses VTF alpha for shader masks, so displaying it as transparency can make a textured weapon's image look blank. Enable **Show texture alpha** to inspect the original transparency. This display choice never changes the 3D material, imported pixels, saved drafts, or exports; PNG/DDS exports retain the original alpha. Click **Export texture**, choose PNG or uncompressed RGBA DDS in the popup, then choose a save location. Export the transparent UV overlay separately if helpful.
   **Copy PNG to clipboard** copies opaque RGB pixels from the original or edited texture at its current dimensions, without the alpha mask or UV lines. Hidden RGB is preserved, not composited onto a background. Only the clipboard texture copy loses transparency: originals, drafts, imports, and PNG/DDS exports retain alpha. **Copy UV overlay to clipboard** copies the visible colored layers on a transparent background at the selected image's dimensions; **Export UV overlay** saves them as a PNG file. Paste into your image editor; overlay transparency support depends on the receiving application.
4. Import an edited PNG or DDS (uncompressed 32-bit RGBA or DXT1/3/5) with the original aspect ratio and supported power-of-two dimensions to preview it on every visible part using that material. Resolution can be higher or lower than the original. Alternatively, copy image pixels in your editor and click **Import from clipboard** on the intended texture. Clipboard images use the same dimension checks and draft behavior; copied text/file paths are not supported, and alpha depends on the source editor. Edits to different materials remain in the assembly preview while you switch parts.
   The first import starts a **local draft** automatically. Further imports, attachment changes, and material selections update that same draft. It stores the weapon, slot selections (including No part), every edited texture, and the active part/material without installing anything in Garry's Mod. Name it at the top of the model view, even before the first import; **Save now** retries a failed save. Wait for **Saved locally · safe to close** before closing the app.
5. For materials on finished `c_` weapons, attachments, and magazines under `materials/models/weapons/v_models` or `materials/models/jarheads/weapons`, choose **Install custom skin**, or **Install all edited textures** to install every edited compatible material in the current assembly. Jarheads sight bodies and flip sights use their exact material paths, just like other weapons. Reticles remain preview-only: the game's `SetupCustomTextures` explicitly ignores material names containing `reticles`. The app converts the preview pixels to VTF with mipmaps and writes:

   - `garrysmod/addons/skins/materials/.../<texture>_custom.vtf`
   - `garrysmod/data/phcustomtextures/.../<material>.vmt`, with `$basetexture` updated to the custom VTF.

   When edited pixels contain non-opaque alpha, installation offers **Keep alpha (recommended)**, **Remove alpha**, or **Cancel**, once per shared VTF. Removal makes only the installed texture opaque; original draft pixels, previews and PNG/DDS exports remain unchanged. Alpha may control transparency or shader masks, so removing it can affect in-game appearance. The chosen installation setting is saved separately so installed status, reinstall and uninstall compare the correct bytes. This warning also applies when installing saved drafts; archived backups restore their original files unchanged.

The **Custom skins** tab lists saved drafts, retained skin backups, and installed custom materials/textures, including incomplete pairs. **Open draft** restores the weapon, attachment choices, edited texture previews, and UV workspace; select the original content folder first so the meshes and materials can be loaded. Drafts remain available even before choosing a Garry's Mod folder. Their status distinguishes **Not installed**, **Installed**, and **Partly installed**, based on matching the actual installed files.

Installing over different custom skin files opens **Replace installed skin?**. Each affected VTF shows the installed texture on the left and the replacement on the right, with opaque RGB previews so alpha masks do not hide the colours; VMT-only changes show scripts. Unavailable previews display an explicit warning. **Cancel** (the default, also Escape) changes no installed files; **Replace entire texture** replaces only the reviewed destinations. Files changed since review require another confirmation. Identical files need no overwrite. This applies to individual textures, all edited textures, saved drafts and backups. Shared VTF replacements affect every installed material referencing that texture. Saved drafts and library entries are retained, but replaced game files are not automatically backed up; export an installed skin first if you need a backup. Failed writes attempt to roll back earlier replacements and report rollback failures.

The installation popup also lists **Models that will change**, including first-time installs. It compares each indexed finished weapon/attachment against its currently PH-mounted material and texture, or original content if no skin is mounted. A shared VTF alone does not count: the model must have different RGBA pixels inside its UV regions or different material settings. A custom texture reference with otherwise unchanged settings/pixels, VMT formatting, and an equivalent nearest-neighbour resolution change do not flag the model. The list is recalculated for the merged result before confirmation. Unreadable installed textures show explicit uncertainty warnings and still allow reviewed replacement; they are not reported as confirmed unchanged. This is a static UV/material comparison, not a complete simulation of Source shaders.

**Merge component textures** is offered when the source draft retains component assignments. It opens a second review showing the actual merged atlas before **Merge and install**. An individual component install applies only that component; all-edited/saved-draft merges apply changed component sources, excluding inherited originals. Installed pixels outside selected UV regions are preserved, with nearest-neighbour scaling to the larger installed/source resolution and no padding outside the selected regions. Alpha removal affects only incoming component regions. Existing VMT settings and mappings are kept; incompatible mappings block merging. All indexed finished weapon/attachment models using that VTF are checked for overlapping UVs: conflicting colours or alpha block the merge, while identical overlapping pixels are safe. Source/installed files are rechecked against the reviewed merged bytes. Flattened VTFs and backups lack component assignments and cannot be merged; mixed component/shared-only edits must be installed separately or explicitly replaced.

A successful merge saves a separate **`<source name> - merged installation`** skin backup before installing. The original editable drafts and library textures stay unchanged. The new merged entry tracks exact installed VMT/VTF files, so its status, export, uninstall and reinstall use the combined result; source drafts retain their normal file-matching status. Uninstall removes the merged installation, not individual component contributions, and does not restore the skin it replaced. Shared VTFs still referenced by other installed materials are retained. If installation fails after saving the merged copy, the error identifies the saved copy and installation is not reported as successful.

**Install** installs a saved draft or backup. **Uninstall** removes matching game files but keeps the local saved copy. For existing installed skins with no draft, Uninstall saves a durable VMT/VTF backup first, which can be reinstalled from the same tab. **Delete skin** removes the saved copy and all matching installed materials/textures, including attachment files and incomplete matching leftovers. Modified files and shared VTFs still referenced by another material are preserved. Without a selected game folder, confirmation warns that deletion can only remove the local copy. **Delete** on an installed-only row permanently removes its game files.

Drafts and backups are stored under the application's Windows app-data directory in `drafts`, separate from Garry's Mod. Draft saves replace their JSON snapshot atomically. Removed attachments' edits remain in the draft and reappear when that part is fitted again. These local drafts are not cloud-synced.

This follows the [PERPHEADS custom skin guide](https://help.perpheads.com/page/using-and-creating-custom-skins): only the VMT is loaded through `data/phcustomtextures`; renamed `_custom.vtf` files are stored under `addons/skins/materials`. These renamed textures do not override the original Workshop texture paths. The original GMA stays untouched. Existing different custom files require explicit overwrite confirmation.

## Current scope

The 3D view shows each model's first bodygroup and root LOD in a static idle pose, with bone-weighted mesh skinning and Lua-selected flip-sight poses. It does not play weapon animations or load animations from external `.ani` files or include models; unavailable requested poses are reported rather than silently replaced. It approximates Source material lighting, so advanced shader effects may differ from the game. Skin installation follows the PERPHEADS guide for first-person weapon materials; other materials can still be inspected, mapped, exported, and previewed.

Attachment slots come from `ui/attachment-data.js`. It covers 55 guns and 99 attachments and records each gun's compatible item-backed attachments, defaults, and per-gun requirements. Revolvers and break-action shotguns have no attachment slots. The file is generated from the gamemode's client Lua (`weaponsystem/sh_attachments.lua`, `weaponsystem/attachments/*.lua`, the item registries, translations, and weapon SWEPs). To regenerate it after a PERPHEADS update:

1. Export the gluapack Lua from a recorded demo with gmoddem: `gmoddem json <demo.dem> -o out.json --gluapack <garrysmod/download/data/gluapack/*.bsp>`. This writes the decoded Lua to an `out.lua` folder. The `LooksLikeLua` check in gmoddem's `Gluapack.cs` must accept non-ASCII bytes; otherwise it stops at the first file with UTF-8 text and the weaponsystem files stay as `return gluapack()()` stubs.
2. Run `pip install lupa`, then `python tools/extract_attachment_data.py out.lua`.

The model, GMA, and VTF readers were adapted from the local demoplayer project. Three.js is vendored under `ui/vendor` with its MIT license.

## Validation

Run `cargo test` from `src-tauri`. When available, set `PERP_TEST_CONTENT` to an extracted PERPHEADS content folder, `PERP_TEST_GMA` to a PERPHEADS `content.gma`, and `PERP_TEST_GMOD` to the installed `garrysmod` folder to enable the corresponding integration checks.

Run `python tools\test_preview.py` for headless rendering and magazine-slot regression checks (requires the Python `playwright` package and Microsoft Edge). These tests verify additive reticle pixels, lighting independence, depth occlusion, thumbnails, imported-texture material settings, and magazine removal/restoration, without moving the mouse or opening a visible browser.

For actual model geometry checks, set `PERP_TEST_CONTENT` and `PERP_PREVIEW_FIXTURES` (an output folder), then run `cargo test dump_preview_fixtures -- --ignored` from `src-tauri`. Run `python tools\test_preview.py --fixtures <output-folder> --screenshot <image.png>` to verify the G36 magazine, flip-sight sequences, and library categories and save headless screenshots.
